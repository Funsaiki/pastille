# Pastille (ex-« Lanceur pastel ») — brief pour Claude Code

## Objectif

Deuxième **lanceur d'applications pour Windows 11** de Funsaiki, en forme de **téléphone pastel** : la fenêtre, transparente, couvre l'écran de la souris ; le téléphone monte du bas de l'écran, incliné, avec des réglages rapides (vue « réglages ») ; le bouton Applications le couche à plat pour afficher les applications (vue « applications »). Il s'ouvre avec un raccourci global et se ferme avec Échap ou quand il perd le focus.

Le premier lanceur est dans le dossier voisin `..\windows-launcher` (dépôt à part) : ce projet en reprend la base (Rust, apps.json, lancements, jeux Steam). Son CLAUDE.md détaille les choix déjà faits et les pièges rencontrés.

Utilisateur : Funsaiki, développeur (TypeScript, Vite, Lit). Il parle français : réponds-lui en français.

- `maquette/Telephone.dc.html` : **la maquette de référence, elle fait foi** (export d'un outil de design ; `support.js` et `vendor/` ne servent qu'à l'afficher). La servir pour la voir : `http://localhost:1420/maquette/Telephone.dc.html` avec `npm run dev`.
- `apps.example.json` : exemple de configuration, même format que le premier lanceur.
- `src/` : le front (Vite + TypeScript) ; `src-tauri/` : Rust.

- `README.md` : la présentation du dépôt public (21/10/2026), en anglais (demande de Funsaiki ; l'interface reste en français, les libellés du menu y sont cités en français). Elle crédite l'inspiration du design, avec l'autorisation de son auteur : le post de u/Single-Flamingo-8194 sur r/unixporn. Les captures de `docs/` (WebP) viennent de l'aperçu navigateur, avec ses données d'exemple : rien de personnel. Les refaire si le design change. Pas de licence, choix de Funsaiki (21/10/2026) : le code se lit, mais ne se réutilise pas ; le README le dit (« All rights reserved »). Ne pas ajouter de fichier LICENSE sans sa demande.

## Règles (à respecter impérativement)

1. **Ne jamais éteindre, redémarrer ni verrouiller la machine.** N'exécute jamais `shutdown`, `rundll32 user32.dll,LockWorkStation` ou équivalent, ni pour tester ni pour vérifier. Dans les builds de développement (`cfg!(debug_assertions)`), les commandes d'alimentation doivent seulement écrire dans le journal. Seul Funsaiki teste ces boutons, sur un build de production, s'il le décide.
2. **Une étape à la fois.** À la fin de chaque étape : le projet compile (`npm run tauri dev` démarre sans erreur), tu fais un commit git, tu donnes à Funsaiki une courte liste de ce qu'il doit vérifier à l'écran, puis **tu attends sa validation** avant l'étape suivante.
3. **Tu ne vois pas la fenêtre.** Pour tout ce qui est visuel, demande à Funsaiki de vérifier ou de te coller une capture d'écran. Aides : les erreurs JS de la fenêtre remontent dans la sortie de `npm run tauri dev` ; l'aperçu navigateur (`http://localhost:1420/`) se capture avec Edge sans interface et se compare à la maquette (même taille, 1440 × 900). Capturer après la fin des animations d'entrée (~1,1 s) : une capture trop tôt montre des tuiles à moitié apparues.
4. **Ne change pas le design sans demander.** Couleurs, tailles, police, espacements, animations et effets de survol restent identiques à la maquette. Si un écart est nécessaire, explique pourquoi et propose avant de le faire.
5. **Pas de modification du système sans accord** : pas d'installation globale, pas de registre, pas de PATH, pas de tâche planifiée.
6. **Travaille dans Windows (PowerShell), jamais dans WSL.**
7. Garde le code simple et lisible ; TypeScript vanilla, pas de framework front (la maquette utilise React, le lanceur non).

Et, comme pour le premier lanceur :
- `autostart` écrit dans le registre (`HKCU\…\Run`) : seul Funsaiki l'active, depuis le menu ; ne jamais le cocher pour tester.
- Ne jamais écrire de test qui lance une cible (`launch`) ou une commande d'alimentation, ni qui simule des frappes réelles.
- Ne pas modifier `src-tauri` pendant que `tauri dev` tourne : il recompile et relance l'app.
- Un nouveau champ dans apps.json est refusé par une version installée plus ancienne (`deny_unknown_fields`) : ne l'écrire chez Funsaiki qu'une fois la nouvelle version lancée.

## Choix techniques

- **Nom : Pastille** (choisi par Funsaiki le 17/10/2026 parmi Pastille, Menthe, Lagon et Mochi : pastel et pilule ; « Lanceur pastel » jusqu'à la 1.6.0) : `productName`, titre des fenêtres, infobulle de l'icône, page de connexion de Spotify ; exe installé `pastille.exe` (`mainBinaryName`). Gardent « lanceur-pastel » : le paquet Cargo (et l'exe de développement) et le dossier ; le dépôt, `phone-pastel-launcher` jusqu'au 21/10/2026, s'appelle `pastille`. Identifiant inchangé (`dev.lanceur.pastel`) : config, connexion à Spotify, épingles et Récents restent. Le nouveau nom donne un nouveau dossier d'installation (`%LOCALAPPDATA%\Pastille`) et une nouvelle entrée dans « Applications installées » : « Lanceur pastel » se désinstalle à part, **sans cocher la suppression des données** (rangées sous l'identifiant, communes aux deux).
- **Tauri v2**, front **Vite + TypeScript**, police **Nunito** embarquée (`@fontsource/nunito`, graisses 700 à 900 : la 600 n'était utilisée nulle part).
- Rust repris du premier lanceur : `config.rs` (apps.json, validation, rechargement, jeux Steam fusionnés, identifiants), `shell.rs` (lancement par `ShellExecuteExW`), `steam.rs`, `tray.rs`, `launcher.rs` (afficher, masquer, raccourci, mode menu clavier d'Alt ignoré), `power.rs` (alimentation, journal seulement en debug), `audio.rs` (volume et micro), `mixer.rs` (volume par application), `media.rs` (Spotify), `spotify.rs` (volume de Spotify par son API web), `feed.rs` (notifications), `tray_apps.rs` (applications de la zone de notification), `tray_host.rs` (zone de notification reprise à Windows, barre pastel cochée), `bar.rs` (barre pastel), `taskbar.rs` (barre des tâches de Windows masquée), `shell_hook.rs` (signaux de la barre des tâches), `system.rs` (profil, relevés), `com.rs` (COM sur un fil à part), `start_menu.rs` (applications du menu Démarrer), `app_menu.rs` (clic droit de la vue applications), `appearance.rs` (carte Personnaliser), `update.rs` (mises à jour depuis les releases). Pas de flou, de jauges ni de recherche de fichiers : la maquette n'en a pas.
- Identifiant **`dev.lanceur.pastel`** (le premier est `dev.lanceur.app`) : config séparée, `%APPDATA%\dev.lanceur.pastel\apps.json`, instance unique et démarrage avec Windows propres à chacun.
- Raccourci **Alt+Espace**, comme le premier lanceur : Funsaiki n'utilise pas les deux en même temps (choix du 14/10/2026). Le second démarré n'obtient pas le raccourci et le signale dans ses notifications : quitter l'autre d'abord (icône > Quitter). Essais de la touche Windows seule : impossibles, voir le CLAUDE.md du premier lanceur.
- Fenêtre : transparente, sans bordure, toujours au-dessus, hors barre des tâches ; Rust la pose sur **tout l'écran de la souris** à chaque ouverture (`cover_cursor_monitor`). Le front met la scène de la maquette (1440 × 900) à l'échelle avec `zoom` (`fitStage`), posée sur le bord bas de l'écran. Un clic à côté du téléphone masque le lanceur (la fenêtre couvre l'écran, il n'y a pas de « clic ailleurs » sinon).
- Icône : tuile « Applications » de la maquette, source `src-tauri/icons/icone.svg` (marche à suivre dans le fichier). Version installée le 15/10/2026, sans remarque de Funsaiki.

## Format de apps.json

Le même que le premier lanceur, sans `fullscreen` (la fenêtre couvre toujours l'écran) :

```jsonc
{
  "accent": "#9fe0dc",
  "shortcut": "Alt+Space",
  "apps": [
    { "label": "Code", "icon": "code", "target": "C:/chemin/Code.exe", "args": ["C:/dev/projet"] },
    { "label": "Jeux", "icon": "jeux", "children": [
      { "label": "Steam", "icon": "bibliotheque", "auto": "steam", "children": [ /* lanceur Steam */ ] }
    ] }
  ],
  "favorites": [ { "label": "Projets", "target": "%USERPROFILE%/Projets" } ]
}
```

- `apps` : tuiles de la vue applications ; un élément avec `children` est un groupe (pastille du nombre d'éléments), les groupes s'imbriquent ; `auto: "steam"` ajoute les jeux Steam détectés (le dernier joué en tête), `auto: "epic"` les jeux Epic (par nom), `auto: "spotify"` les titres likés et les playlists de Spotify une fois connecté (1.2.0 et plus), `auto: "start"` les applications du menu Démarrer (1.5.0 et plus) ; une autre valeur d'`auto` est refusée.
- Lancements comptés dans `usage.json` (à côté de apps.json, clé = cible et arguments), envoyés au front dans les champs `uses` et `last` (jamais lus dans apps.json).
- `favorites` : rangée « Dossiers » sous les applications (4 colonnes ; au-delà, une deuxième rangée déborderait).
- `source` est accepté mais pas affiché (la maquette n'a pas de sous-titre sous les tuiles).
- `keywords` : mots trouvés par la recherche, en début de mot.
- À la place de `target` (1.8.0 et plus, pour les PC dont les chemins diffèrent) : `app`, le nom d'une application du menu Démarrer (`"app": "Visual Studio Code"`, sans majuscules ni accents qui comptent), ou `default`, le programme par défaut de Windows pour un protocole ou une extension (`"default": "https"` : le navigateur ; `".pdf"`). Un seul des trois ; `args` seulement avec `target`. Introuvable sur le PC : la tuile n'est pas affichée. **Un groupe vide n'est pas affiché** (Epic pas installé, groupe `start` avant la première lecture du menu Démarrer). **Un groupe `auto` auquel rien n'a été ajouté et qui n'a plus qu'un élément à lui** (Spotify pas connecté, Steam sans jeux) devient cet élément, sous le libellé et l'icône du groupe (mots-clés des deux, même id que le groupe ; `added` marque ce que les groupes `auto` ajoutent) : la tuile lance directement, sans groupe d'une seule tuile.
- Dossiers : `shell:Downloads`, `shell:Personal` (Documents), `shell:Desktop`, `shell:Screenshots`, `shell:My Pictures`… suivent un dossier déplacé (OneDrive, autre disque), au contraire de `%USERPROFILE%\Downloads`.

### Ajout — Zone de notification de Pastille (demandée par Funsaiki le 18/10/2026, validée le 19/10/2026 : « tout fonctionne bien » ; EarTrumpet reste à essayer)
- Origine : avec la barre pastel, l'icône d'EarTrumpet (mixeur de volume) relançait le programme au lieu d'ouvrir son mixeur (EarTrumpet n'a pas de fenêtre ; une seconde copie voit la première et s'arrête, vérifié dans son code). Deux solutions proposées : un cas à part pour EarTrumpet, ou reprendre la zone de notification à Windows comme RetroBar ; choix de Funsaiki : la seconde (« autant faire le chantier tout de suite »).
- `tray_host.rs`, seulement barre pastel cochée, sur le fil de taskbar.rs (créée après le masquage de la barre de Windows, détruite avant son retour) : fenêtre cachée de classe `Shell_TrayWnd` (même rectangle que celle de Windows, `WS_EX_TOPMOST`, jamais affichée : `SWP_SHOWWINDOW` retiré), que `Shell_NotifyIcon` trouve avant celle de Windows ; gardée devant toutes les 250 ms (`keep_first`, ~7 µs). WM_COPYDATA `dwData` 1 (SHELLTRAYDATA, NOTIFYICONDATA en forme 32 bits) lu : fenêtre, identifiant ou GUID, message de rappel, version (`NIM_SETVERSION`), infobulle, masquée (`NIS_HIDDEN`). **Tout est transmis à la barre de Windows** (`SendMessageTimeoutW`, 4 s), qui reste à jour (bulles devenues notifications, icônes là quand la barre pastel est coupée) : WM_COPYDATA (icônes, barres d'applications, position des icônes), WM_COMMAND et WM_USER à 0xBFFF ; pas les messages inscrits (diffusés, elle les a). Icône acceptée : réponse 1, même si Windows refuse un doublon.
- Icônes déjà là au démarrage : « TaskbarCreated » envoyé aux seules fenêtres des programmes qui tournent et ont déjà eu une icône (registre `NotifyIconSettings`, sans Windows ni Pastille : `tray_apps::tray_pids`), pas à tout le système. Explorateur relancé (son « TaskbarCreated » reçu) : notre fenêtre remise devant et icônes redemandées 2 s plus tard. `taskbar::for_each_bar` ignore notre fenêtre (`tray_host::own`).
- Liste (onglet Apps et ^ de la pilule) : une tuile par icône visible (clé `#n`), fenêtre encore en vie, sans Windows ni Pastille ; nom et icône du programme comme avant (les icônes de la zone font 16 px à 100 % : floues en 24) ; infobulle actuelle au survol. Puis, comme avant (Ouvrir au clic), les programmes du registre qui tournent sans avoir donné d'icône à Pastille : sans icône en ce moment (Spotify, vérifié par `Shell_NotifyIconGetRect`), ou qui ignorent « TaskbarCreated » (Riot Client, Java Update Checker : vérifié en le leur envoyant directement) et n'arrivent qu'en changeant leur icône ou en redémarrant. Barre pastel coupée : la liste du registre seule.
- Premier essai (19/10/2026) : notre fenêtre trouvée en premier 100 fois sur 100. Des tuiles à l'initiale (pilule, onglet Apps) : `SHGetFileInfoW` échoue quand deux fils lisent la même icône en même temps (reproduit hors de Pastille, avec 2 et 4 fils : Brave, Discord), et l'échec restait en mémoire ; les icônes sont maintenant lues une à la fois (`icon.rs`, `READING`, test `same_icon_read_together_is_read_by_all`, qui échoue sans le verrou).
- Clics (`tray_click`) : les messages que la barre de Windows enverrait, `SendNotifyMessageW` après `AllowSetForegroundWindow` : gauche = WM_LBUTTONDOWN, WM_LBUTTONUP (+ NIN_SELECT depuis la version 3) ; second clic d'un double clic = WM_LBUTTONDBLCLK, WM_LBUTTONUP (+ NIN_SELECT) ; droit = WM_RBUTTONDOWN, WM_RBUTTONUP (+ WM_CONTEXTMENU) : **le menu de l'application** ; milieu = WM_MBUTTONDOWN, WM_MBUTTONUP ; Entrée = NIN_KEYSELECT. Version 4 : l'identifiant avec l'événement, la souris en point d'ancrage ; avant : l'identifiant dans wParam. Icône sans message de rappel : Ouvrir comme avant.
- Position de l'icône (`Shell_NotifyIconGetRect`, WM_COPYDATA `dwData` 3, deux messages : coin haut gauche puis bas droit) : Pastille répond pour une icône cliquée chez elle, un pixel sous la souris du dernier clic sur sa tuile ; sinon la barre de Windows répond. Remarqué par Funsaiki le 19/10/2026 : certains menus s'ouvraient au coin bas droit de l'écran, la place de la flèche de la barre de Windows masquée.
- Front : **Maj+clic droit** (ou touche Menu) ouvre le menu de Pastille (Ouvrir = clic gauche, Emplacement, Forcer à quitter), comme Maj+clic droit sur un bouton de la barre de Windows. Pilule : la zone se referme 0,5 s après un clic gauche (le temps d'un double clic) ; au clic droit, elle reste ouverte et le menu de l'application s'ouvre par-dessus (demande de Funsaiki, 19/10/2026 : la première version la refermait). Téléphone : il se masque quand l'application passe au premier plan (sa fenêtre, son menu), pas avant (second clic d'un double clic). Aperçu : EarTrumpet dans la liste, clics dans la console ; vérifié avec une vraie souris (`tray-verif.mjs` du dossier temporaire).
- Tests : lecture des messages, suivi des icônes (identifiant et GUID), forme des clics, clic reçu par une fenêtre du test. **Jamais la vraie fenêtre dans un test** (toutes les icônes du PC y passeraient). Journal de développement : « zone de notification : icône de <pid> ».
- Risques annoncés à Funsaiki : toutes les icônes passent par Pastille (figée, une application qui change son icône attend jusqu'à 4 s… comme avec une barre de Windows figée) ; des programmes qui cherchent la barre de Windows trouvent la nôtre (même rectangle, messages transmis).

## Pièges connus (repris du premier lanceur)

- **Transparence** : `transparent: true` + `decorations: false` + `shadow: false` **et** fond CSS transparent sur `html` et `body`.
- **Alt + Espace** ouvre normalement le menu système des fenêtres ; le lanceur le remplace tant qu'il tourne (Funsaiki le sait).
- **Survol mort après le raccourci** : relâcher Alt quand le lanceur a pris le focus le passe en mode menu clavier, qui retient la souris. `SC_KEYMENU` est ignoré par sous-classement (`disable_key_menu`).
- **Image figée et processeur** : retirer la scène de l'affichage (`hidden`) avant de masquer la fenêtre ; sinon l'ancienne image réapparaît un instant, et les animations en boucle (égaliseur) tournent derrière la fenêtre masquée (~9 % d'un cœur mesuré sur le premier lanceur).
- **Outils de développement** : les ouvrir fait perdre le focus ; en debug, le lanceur reste affiché tant qu'ils sont ouverts.
- **Plusieurs écrans** : le lanceur s'ouvre sur l'écran de la souris.
- **Texte flou en vue applications** (remarqué par Funsaiki après l'agrandissement de 10 %) : un élément dans un calque à part (« composité ») est dessiné une fois puis étiré ; la vue était dessinée à 946 px de large puis affichée à 1 040. Causes trouvées avec le protocole DevTools (`LayerTree.compositingReasons`, script `cdp-layers.mjs` du dossier temporaire) : une animation finie qui garde son état (`both`) reste « active » (`tp-land`, `tp-rise`, pages de la grille, balancement du strap) ; une transformation avec `rotateX(0)` ou `translateZ` reste de la 3D. Corrigé : ces animations sont retirées une fois jouées (`playOnce`, fin du balancement) ; une fois couché, le téléphone passe à plat (`.settled`, 750 ms après la rotation : sans perspective, transformation 2D, sans `translateZ` sur le corps et le strap), sans transition dans les deux sens (`setSettled`, classe `.settling`). Edge sans interface ne montre pas le flou : vérifier les calques, et faire juger Funsaiki. **Revenu le 19/10/2026** (WebView2 155) : le curseur du champ de recherche, qui a le focus dès la rotation, est un calque à part (« Is a caret in an editor », même immobile ou transparent), et tout ce qui était peint après lui (compte, heure, haut de la grille) passait dans un second calque, flou jusqu'au premier clic (le focus quitte la recherche). Corrigé : la recherche est peinte en dernier dans la vue (`position: relative; z-index: 1`, sous les menus à 2), plus de second calque ; captures identiques à l'œil (lissage des bords seulement). Relevé sur la vraie fenêtre : `$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS = '--disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection --remote-debugging-port=9223'` avant `npm run tauri dev` (cette session seulement), puis le protocole DevTools sur ce port ; Edge sans interface avec `Emulation.setFocusEmulationEnabled` montre aussi le curseur.
- **Fenêtre console** : toute commande lancée depuis Rust doit utiliser `CREATE_NO_WINDOW`.
- **Projet déplacé** : Cargo garde des chemins absolus dans `target` ; après un déplacement, `cargo clean`.
