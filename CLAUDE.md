# Pastille (formerly "Lanceur pastel") — brief for Claude Code

## Goal

Funsaiki's second **app launcher for Windows 11**, shaped like a **pastel phone**: the transparent window covers the screen the mouse is on; the phone rises from the bottom of the screen, tilted, with quick settings (the "quick settings" view); the Apps button lays it flat to show the apps (the "apps" view). It opens with a global shortcut and closes with Escape or when it loses focus.

The first launcher is in the sibling folder `..\windows-launcher` (separate repo): this project reuses its base (Rust, apps.json, launching, Steam games). Its CLAUDE.md details the choices already made and the pitfalls met.

User: Funsaiki, developer (TypeScript, Vite, Lit). Funsaiki speaks French: **always answer in French.**

## Rules (must be followed)

1. **Never shut down, restart or lock the machine.** Never run `shutdown`, `rundll32 user32.dll,LockWorkStation` or an equivalent, not even to test or check. In development builds (`cfg!(debug_assertions)`), power commands must only write to the log. Only Funsaiki tests these buttons, on a production build, if Funsaiki decides to.
2. **One step at a time.** At the end of each step: the project compiles (`npm run tauri dev` starts without errors), you make a git commit, you give Funsaiki a short list of what to check on screen, then **you wait for validation** before the next step.
3. **You can't see the window.** For anything visual, ask Funsaiki to check or to paste a screenshot. Helpers: JS errors from the window show up in the output of `npm run tauri dev`; the browser preview (`http://localhost:1420/`) can be captured with headless Edge and compared with the mockup (same size, 1440 × 900). Capture after the entrance animations end (~1.1 s): a capture taken too early shows half-appeared tiles.
4. **Don't change the design without asking.** Colors, sizes, font, spacing, animations and hover effects stay identical to the mockup. If a deviation is needed, explain why and propose it before doing it.
5. **No system changes without agreement**: no global install, no registry, no PATH, no scheduled task.
6. **Work in Windows (PowerShell), never in WSL.**
7. Keep the code simple and readable; vanilla TypeScript, no front-end framework (the mockup uses React, the launcher doesn't).

And, as for the first launcher:
- `autostart` writes to the registry (`HKCU\…\Run`): only Funsaiki turns it on, from the Settings page; never turn it on to test.
- Never write a test that launches a target (`launch`) or a power command, or that simulates real keystrokes.
- Don't modify `src-tauri` while `tauri dev` is running: it recompiles and restarts the app.
- A new field in apps.json is rejected by an older installed version (`deny_unknown_fields`): only write it on Funsaiki's PC once the new version is running.

## Technical choices

- **Name: Pastille** (chosen by Funsaiki on 2026-10-17 among Pastille, Menthe, Lagon and Mochi: pastel and pill; "Lanceur pastel" up to 1.6.0): `productName`, window titles, tray icon tooltip, Spotify connection page; installed exe `pastille.exe` (`mainBinaryName`). Still "lanceur-pastel": the Cargo package (and the development exe) and the folder; the repo, `phone-pastel-launcher` until 2026-10-21, is called `pastille`. Identifier unchanged (`dev.lanceur.pastel`): config, Spotify connection, pins and Recent are kept. The new name gives a new install folder (`%LOCALAPPDATA%\Pastille`) and a new entry in "Installed apps": "Lanceur pastel" is uninstalled separately, **without ticking the deletion of the data** (stored under the identifier, shared by both).
- **Tauri v2**, front **Vite + TypeScript**, **Nunito** font bundled (`@fontsource/nunito`, weights 700 to 900: 600 was used nowhere).
- Rust taken from the first launcher: `config.rs` (apps.json, validation, reloading, merged Steam games, identifiers), `shell.rs` (launching through `ShellExecuteExW`), `steam.rs`, `tray.rs`, `launcher.rs` (show, hide, shortcut, Alt's keyboard menu mode ignored), `power.rs` (power, log only in debug), `audio.rs` (volume and mic), `mixer.rs` (per-app volume), `media.rs` (Spotify), `spotify.rs` (Spotify's volume through its web API), `feed.rs` (notifications), `tray_apps.rs` (notification area apps), `tray_host.rs` (notification area taken over from Windows, pastel bar on), `bar.rs` (pastel bar), `taskbar.rs` (Windows taskbar hidden), `shell_hook.rs` (taskbar signals), `system.rs` (profile, stats), `com.rs` (COM on a separate thread), `start_menu.rs` (Start menu apps), `app_menu.rs` (right-click in the apps view), `appearance.rs` (Customize card), `update.rs` (updates from the releases), `prefs.rs` (Settings page), `i18n.rs` (French and English). No blur, gauges or file search: the mockup has none.
- Identifier **`dev.lanceur.pastel`** (the first one is `dev.lanceur.app`): separate config, `%APPDATA%\dev.lanceur.pastel\apps.json`, single instance and start with Windows specific to each.
- Shortcut **Alt+Space**, like the first launcher: Funsaiki doesn't use both at the same time (choice of 2026-10-14). The second one started doesn't get the shortcut and says so in its notifications: quit the other one first (icon > Quit). Attempts with the Windows key alone: impossible, see the first launcher's CLAUDE.md.
- Window: transparent, borderless, always on top, not in the taskbar; Rust places it over **the whole screen the mouse is on** at each opening (`cover_cursor_monitor`). The front scales the mockup's stage (1440 × 900) with `zoom` (`fitStage`), sitting on the bottom edge of the screen. A click beside the phone hides the launcher (the window covers the screen, so there's no "click elsewhere" otherwise).
- Icon: the mockup's "Applications" tile, source `src-tauri/icons/icon.svg` (instructions in the file). Installed version on 2026-10-15, with no remark from Funsaiki.

## apps.json format

The same as the first launcher, without `fullscreen` (the window always covers the screen):

```jsonc
{
  "accent": "#9fe0dc",
  "shortcut": "Alt+Space",
  "apps": [
    { "label": "Code", "icon": "code", "target": "C:/path/Code.exe", "args": ["C:/dev/project"] },
    { "label": "Games", "icon": "games", "children": [
      { "label": "Steam", "icon": "library", "auto": "steam", "children": [ /* Steam launcher */ ] }
    ] }
  ],
  "favorites": [ { "label": "Projects", "target": "%USERPROFILE%/Projects" } ]
}
```

- `apps`: tiles of the apps view; an item with `children` is a group (badge with the number of items), groups nest; `auto: "steam"` adds the detected Steam games (last played first), `auto: "epic"` the Epic games (by name), `auto: "spotify"` Spotify's liked songs and playlists once connected (1.2.0 and later), `auto: "start"` the Start menu apps (1.5.0 and later); any other `auto` value is rejected.
- Launches counted in `usage.json` (next to apps.json, key = target and arguments), sent to the front in the `uses` and `last` fields (never read from apps.json).
- `favorites`: "Folders" row under the apps (4 columns; beyond, a second row would overflow).
- `source` is accepted but not shown (the mockup has no subtitle under the tiles).
- `keywords`: words found by the search, at the start of a word.
- Instead of `target` (1.8.0 and later, for PCs whose paths differ): `app`, the name of a Start menu app (`"app": "Visual Studio Code"`, case and accents don't matter), or `default`, Windows' default program for a protocol or an extension (`"default": "https"`: the browser; `".pdf"`). Only one of the three; `args` only with `target`. Not found on the PC: the tile isn't shown. **An empty group isn't shown** (Epic not installed, `start` group before the first read of the Start menu). **An `auto` group to which nothing was added and which has only one item of its own left** (Spotify not connected, Steam without games) becomes that item, under the group's label and icon (keywords of both, same id as the group; `added` marks what `auto` groups add): the tile launches directly, without a one-tile group.
- Folders: `shell:Downloads`, `shell:Personal` (Documents), `shell:Desktop`, `shell:Screenshots`, `shell:My Pictures`… follow a moved folder (OneDrive, another drive), unlike `%USERPROFILE%\Downloads`.

## Plan

### Step 1 — Project and mockup (validated by Funsaiki on 2026-10-14, with the animation tweaks)
- Project created from the first launcher; mockup ported into `index.html`, `src/styles.css`, `src/ui.ts`.
- Apps view wired like in the first launcher: apps.json, nested groups, Steam games, folders, launching, search (label anywhere, keywords at the start of a word, 16 results at most like the mockup; Enter launches the first one).
- Choices made, to be validated by Funsaiki:
  - Pages: one row of 8 above the folders, two rows (16) inside a group; wheel, arrows at the edge, Page Up/Down; the mockup's `tp-in-r` / `tp-in-l` animations. No page indicator (it would be an addition to the design).
  - Escape: in the apps view, acts like the back button (clears the search, goes up one group, returns to quick settings); in the quick settings view, hides the launcher.
  - Typing a character in the quick settings view opens the apps view with the search started.
  - Errors: config problems and failed launches at the top of the notifications; a failed launch also replaces the apps view's overline ("Couldn't launch", full message on hover).
- The rest of the quick settings view keeps the mockup's data (Bluetooth, mic, audio output, volume, now playing, sample notifications); the clock is real (network speed and profile: step 2). The top buttons do nothing.

### Step 2 — Status and profile (validated by Funsaiki on 2026-10-14)
- First name and initial: first word of the Windows account's display name (`GetUserNameExW`; otherwise `%USERNAME%`). "Windows 11" from the build number (ProductName still says "Windows 10"). system.rs, `profile` command.
- Real network speed (`network` command): bytes of the connected physical adapters (`GetIfTable2`), without virtual adapters (Hyper-V, WSL, Docker, VPN) or each adapter's filter layers, which repeat its counters (checked: three layers on an Ethernet adapter). Polled every second, only while the quick settings view is shown; on opening, first measure over 250 ms. KB and MB of 1024; MB/s from 1,000 KB/s, one decimal below 10 MB/s.

### Step 3 — Top buttons (validated by Funsaiki on 2026-10-14)
- Settings (`ms-settings:`): `open_tool` command, the front sends a name (`settings`), not a target. The launcher hides after opening; a failure shows in the notifications ("Launch").
- File Explorer and Lock existed, then were removed at Funsaiki's request after step 6 (with the row of buttons); the matching Rust code too.
- Power (Funsaiki's request): opens the power menu, which acts as a double check like in Windows. Sleep, Shut down, Restart, Sign out. Cancel, Escape or a click on the darkened screen closes it; Enter cancels (Cancel has focus on opening); up and down arrows between the buttons; the quick settings view is `inert` behind. After a successful choice, the launcher goes down; a failure shows in the menu.
- `power.rs`: sleep through `SetSuspendState`, started 0.8 s later on a separate thread to let the launcher hide (otherwise it would reappear on wake, frozen); `IsPwrSuspendAllowed` checked first. Shut down, restart, sign out: `shutdown.exe /s /t 0`, `/r /t 0`, `/l`. **In debug, one log line only (rule 1).** Funsaiki will try these buttons on the installed version (step 8).

### Step 4 — Sound and performance (validated by Funsaiki on 2026-10-14)
- Volume: that of the default output in the Sound settings (`IAudioEndpointVolume`, `audio.rs`), read again each time the quick settings view is shown. The slider changes it live; one send at a time, the last level wins. Moving the slider unmutes the sound if it was muted (like Windows); muted or 0%: crossed-out speaker icon. Without an audio output: slider disabled, "No output".
- Mic: mutes or unmutes the default mic ("On" / "Muted", "No mic" if there is none). Mutes the mic for every app that uses it.
- Audio output removed (Funsaiki never changes output); "Stay awake" ruled out too. Instead, Performance: processor (the "% Processor Utility" counter, Task Manager's, capped at 100) and physical memory used, read with the network speed (`stats` command, formerly `network`); a click opens Task Manager (`open_tool` `taskmgr`).
- Failures (volume, mic) in the notifications.
- Bluetooth tile removed. Apps over the full width.

### Step 5 — Now playing (validated by Funsaiki on 2026-10-14)
- **Spotify only** (Funsaiki uses it all the time, no need for other players): session of Windows' media controls (`GlobalSystemMediaTransportControlsSessionManager`, `media.rs`) whose identifier contains "spotify" (Microsoft Store version: `SpotifyAB.SpotifyMusic_…!Spotify`).
- Real title and artist (full title on hover), equalizer animated only while playing; previous, play/pause, next control Spotify. Read when the quick settings view is shown, then every second with the stats (~20 ms). After a click, play/pause changes right away and reads wait 0.5 s (Spotify still announces the old state).
- Spotify closed: "Nothing playing" / "Spotify is closed", buttons grayed out (opacity .4, addition to the mockup).
- Failures in the notifications ("Playback"). Tests never control Spotify.

### Step 6 — Mixer (requested by Funsaiki, validated on 2026-10-14)
- Replaces the planned Bluetooth step (dropped).
- `mixer.rs`: audio sessions of the default output (`IAudioSessionManager2`), except those of closed apps, grouped by program; system sounds apart. Name: the program's description (version info, "Brave Browser"), otherwise the file name ("wallpaper32"). Spotify gives the length of its description in bytes: reading stops at the first null character. Order: those playing sound, then by name, system sounds last. ~15 ms.
- Volume relative to the master volume, like in Windows; moving a slider unmutes the app if it was muted. One send at a time per app (`latestOnly`, shared with the master volume).

## Known pitfalls (taken from the first launcher)

- **Transparency**: `transparent: true` + `decorations: false` + `shadow: false` **and** a transparent CSS background on `html` and `body`.
- **Alt + Space** normally opens the windows' system menu; the launcher replaces it while it runs (Funsaiki knows).
- **Dead hover after the shortcut**: releasing Alt when the launcher has taken focus puts it in keyboard menu mode, which holds the mouse. `SC_KEYMENU` is ignored through subclassing (`disable_key_menu`).
- **Frozen image and CPU**: remove the stage from rendering (`hidden`) before hiding the window; otherwise the old image reappears for a moment, and looping animations (equalizer) keep running behind the hidden window (~9% of one core measured on the first launcher).
- **Developer tools**: opening them makes the window lose focus; in debug, the launcher stays shown while they're open.
- **Several screens**: the launcher opens on the mouse's screen.
- **Blurry text in the apps view** (noticed by Funsaiki after the 10% enlargement): an element in its own layer ("composited") is drawn once then stretched; the view was drawn 946 px wide then shown at 1,040. Causes found with the DevTools protocol (`LayerTree.compositingReasons`, script `cdp-layers.mjs` in the temporary folder): a finished animation that keeps its state (`both`) stays "active" (`tp-land`, `tp-rise`, grid pages, strap swing); a transform with `rotateX(0)` or `translateZ` stays 3D. Fixed: these animations are removed once played (`playOnce`, end of the swing); once laid flat, the phone goes flat (`.settled`, 750 ms after the rotation: no perspective, 2D transform, no `translateZ` on the body and the strap), without transition both ways (`setSettled`, `.settling` class). Headless Edge doesn't show the blur: check the layers, and let Funsaiki judge. **Came back on 2026-10-19** (WebView2 155): the search field's caret, which has focus from the rotation on, is its own layer ("Is a caret in an editor", even still or transparent), and everything painted after it (count, clock, top of the grid) went into a second layer, blurry until the first click (focus leaves the search). Fixed: the search is painted last in the view (`position: relative; z-index: 1`, under the menus at 2), no more second layer; screenshots identical to the eye (edge antialiasing only). Reading the real window: `$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS = '--disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection --remote-debugging-port=9223'` before `npm run tauri dev` (this session only), then the DevTools protocol on that port; headless Edge with `Emulation.setFocusEmulationEnabled` also shows the caret.
- **Console window**: any command launched from Rust must use `CREATE_NO_WINDOW`.
- **Project moved**: Cargo keeps absolute paths in `target`; after a move, `cargo clean`.
